## Pass Criteria

- No crash during startup, navigation, cloud configuration, or model selection.
- MNN multimodal release admission requires one representative compatible ARM64
  device to pass both production surfaces with the same APK: a real image sent
  through MainActivity UI and an authenticated OpenAI-compatible `image_url`
  request through Local API. Debug activities, direct native calls, and internal
  smoke runners are diagnostic evidence only and do not count as final
  acceptance.
- After that representative UI + Local API gate passes, MNN vision is opened by
  default on all compatible ARM64 devices. A later device-specific failure is
  handled as an explicit exception or targeted optimization, not as a reason to
  restore a global per-device allowlist.
- UI and API must have different request IDs, increasing native sequences,
  exactly one prepared image per single-image request, different image hashes,
  stable model/profile/active/committed/effective signatures, and
  `RuntimeOverride=NONE`. Each terminal snapshot must report `busy=false`,
  `code=idle`, `engineLifecycle=ready`, and `generationActive=false`.
- Local image generation can fail only with an actionable model-bundle or device
  explanation.
- Snapdragon NPU claims must include the exact SoC, QNN runtime detection state,
  model-bundle id, smoke-test dimensions, step count, elapsed time, and whether
  execution was proven through QNN/HTP logs.
- Logs, screenshots, and exported diagnostics contain no API keys or private
  user content before they are shared.
- Device-specific performance claims include model name, quantization, image
  size, steps, thread count, elapsed time, and thermal state.
