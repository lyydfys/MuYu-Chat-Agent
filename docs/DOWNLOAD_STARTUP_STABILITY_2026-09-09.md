# 下载、导入与启动恢复修复

本次针对“推荐页下载时退出、之后无法打开应用”的反馈，修复静态审计中确认的风险。故障手机的 APK 身份、退出原因和堆栈尚未取得，因此不能把本次代码风险直接认定为该手机的实际崩溃根因。

## 行为变化

- 启动由独立的启动 ViewModel 管理，数据库和本地记录初始化在 IO 线程执行。失败时保留可操作的恢复页，支持重试、暂缓模型扫描和复制诊断信息，不清除模型或聊天记录。
- 启动前记录尝试状态，成功后结束该状态；未完成的启动在下次打开时进入恢复页。诊断记录包含主进程最近的 Android 退出原因、剩余空间和启动异常，正常诊断导出也包含这份记录。
- 首次界面只读取已保存的图像模型目录，模型发现与旧 SHA 迁移在后台完成。发现过程真正限制遍历深度，跳过临时安装目录；单条损坏记录不丢弃其他模型，并保留原始损坏清单供恢复。
- Compose 在后台准备模型能力和 readiness 快照，重组时只消费快照。历史图片元数据按图片列表缓存，本地模型卡片逐条惰性组合。
- 推荐模型和远程文件下载统一使用 WorkManager 持久任务，包含下载、校验、解压、注册全过程。同一任务去重，多任务安装串行执行；模型页和系统通知提供暂停操作。
- 分片保存在与目标相同文件系统的模型目录中，避免缓存淘汰和跨挂载点提交失败；来源身份区分仓库、版本和文件。完整文件的本地校验收据支持“文件已完成、注册未完成”的恢复，这份收据不冒充发布者提供的完整性证据。
- 下载动态保留 128 MiB 运行空间，存储不足不进入网络重试循环。QAIRT ZIP 解压检查展开大小、路径、CRC 和剩余空间，完成的条目可在重试时复用。
- 模型包在候选目录处理后提交，注册失败时恢复旧包并保留新包供重试；上次中断留下的备份不会被直接当作垃圾删除。生图源 ZIP 保留到注册完成。
- 导入、刷新、加载前置检查和成功结果发布纳入同一个异常边界；协程取消继续传播。恢复目录时清单写入失败保留可读取的列表，正式注册仍需成功保存。

## 使用边界

Android 的“强行停止应用”会阻止后台任务运行，重新打开应用后才能恢复调度。正常进程回收、网络约束变化和设备重启由 WorkManager 恢复任务；存储不足、格式错误等明确失败，以及用户主动暂停，需要处理原因后再次点击下载。

旧版本没有持久任务身份的缓存分片不会被猜测来源后拼接到新任务，也不会在本次修复中被清理。下载成功与推理可用仍分开：实际模型加载和执行验证保留原有检查。设备身份只影响推荐排序和运行时选择，不作为准入名单。

MNN CPU high precision、加载签名验证及 vendor patch 均未因本次稳定性修复而变更。工作树原有的其他改动保留。

## 真机复验步骤

1. 记录手机、Android 版本、可用空间、APK SHA256、目标模型与来源；使用普通用户前端从推荐页开始下载。
2. 分别在网络下载、解压、注册阶段中断应用进程，然后重新打开；确认首屏可响应、任务恢复、已有模型仍可加载、完成后只出现一个对应模型。
3. 下载途中断网再联网；从通知及模型页分别暂停，然后重新点击同一模型。核对续传字节和最终文件校验，不仅查看文件夹是否存在。
4. 在可控测试存储环境触发低空间，检查保留空间、可读错误、旧模型和分片保留；释放空间后完成同一任务。不要用填满用户真实数据盘的方式制造条件。
5. 测试数据库读取失败、旧 SHA 缺失、损坏的单条模型记录、深目录和大型模型目录；确认恢复页可操作，正常打开后不在主线程执行模型哈希。
6. 分别下载 MNN、GGUF、LiteRT-LM、QAIRT 聊天包、多模态包、生图多组件包和 ZIP 包；确认注册、选择、自动加载入口及前端错误提示。
7. 导出诊断并收集 logcat、退出原因及安装身份。本地主机测试不能替代这些设备证据。
