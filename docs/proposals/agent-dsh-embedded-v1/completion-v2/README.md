# MCA DSH 补齐方案 V2：官方账号、MCA 模型与手机版全能力

日期：2026-10-20（Asia/Shanghai）。交付类型：设计与交接文档；**不实施、不修改生产代码、不构建或登录账号**。

## 1. 本版目标与规范关系

在 MCA 的独立 DSH 页面运行真正的 DSH 内核与前端，保留官方 Agent 循环、会话、工具、审批、压缩、子 Agent、插件和配置体系；补齐 Android 宿主和必要的平台适配。模型入口同时支持：

1. **DeepSeek 账号登录**：复用 DSH 官方账号认证和账号模型 provider，使用外部浏览器完成官方登录，不要求用户用 API Key 代替账号。
2. **MCA 本地模型**：通过现有受认证的 loopback 模型网关调用 MCA 实际推理 owner，生成在手机上运行。
3. **MCA 云端模型**：通过同一网关使用 MCA 已配置云模型；凭据留在 MCA，不复制到 DSH 配置。

账号模型使用网络服务；本地运行 DSH 不等于账号模型离线推理。完整离线须单独验证本地模型、辅助模型、工具和依赖闭包。

用户指定的手机版参照仅为 **`woaiys3/deepseek-harness-android-app`**，固定读取版本 `98162a23b39eeeb75b8d4608b3e773bbb13be43d`（2026-10-18，v1.20.1）。**它不是 `DSH-APP/DSHA`**。后者只保留为历史备选研究，不替代本版主对标对象。

V2 补充并修订 [V1方案](../DSH_COMPLETION_PLAN_V1_20261020.md)、[V1执行包](../DSH_COMPLETION_EXECUTION_PACK_V1.md) 的目标范围与待执行事项，不重写旧证据、不把旧C卡重新算完成。源码已有修复应复用并复测，不重新实现。项目硬锁及 [ADR0003](../../../adr/0003-dsh-embedded-dual-agent-modes.md) 继续生效。

## 2. 产品形态与不可变边界

保持侧栏 **图片 → Agent → DSH**。原生 Kotlin Agent 与 DSH 各自独立，原生 Agent 的 third-party 补齐方案不作为 DSH 的运行依赖。

DSH 页面仍显示官方 Web UI，不用 Kotlin 重做聊天、插件市场、审批、工具执行循环或会话库。宿主增加的是 DSH 专属的“运行与手机能力”管理面：状态、权限、浏览器/虚拟屏、诊断、备份恢复、安全模式和入口。它不重排 MCA 聊天、生图、模型管理及全局设置。

| 责任 | 唯一权威方 |
| --- | --- |
| Agent loop、工具调度/审批、session、子Agent、压缩、插件安装配置 | 官方 DSH |
| DeepSeek 账号流程、账号凭据状态和账号请求协议 | 官方 DSH 账号模块；Android只适配浏览器/生命周期 |
| Node/服务/子进程生命周期、payload、维护事务 | 既有 DshRuntimeOwner 与宿主平台实现 |
| 本地/云模型目录及实际推理、模型lease/取消 | MCA既有模型业务与执行owner |
| Android动作、浏览器、无障碍、虚拟屏与各自资源 | 窄类型平台owner，DSH插件通过受认证能力端点调用 |
| 页面/控制台 | 只读投影与typed intent，无数据库/engine/任意shell持有权 |

任意时刻只有一个受管生产 DSH 宿主 Node。工具子进程不等于第二宿主；受控候选trial与生产宿主串行。共享模型资源仍由实际 MCA 仲裁者管理，不为 DSH 或控制台另建推理引擎。
