# MCA v0.4.3 — 全应用统一的文本输入框清空

## 1. 一句话

项目曾有 **95 个文本输入框，只有 3 个能一键清空**。这一版把清空按钮做成输入框控件自带的属性，**91 处调用点已统一迁移**。

## 2. 问题

输错一个字要长按、全选、再删。温度、Top-P、API Key、预设名、角色描述这些地方都是如此。

根因不是各页面偷懒，而是 `core:designsystem` 里没有统一的文本输入框组件 —— 95 处都是各自直接调 `OutlinedTextField`，清空按钮因此无从统一。

## 3. 新增共享控件 `McaTextField`

`core/designsystem/.../McaTextField.kt`

```kotlin
McaTextField(
    value = text,
    onValueChange = { text = it },
    label = { Text("温度") },
    singleLine = true,
)
```

清空按钮由组件自己提供，调用方不用写 `trailingIcon`，也不用写清空逻辑。

### 显示规则

| 条件 | 清空按钮 |
|---|---|
| `value` 为空 | 不显示 |
| `enabled = false` | 不显示 |
| `readOnly = true` | 不显示 |
| 调用方传了 `trailingIcon` | 不显示（调用方图标优先） |
| 其余情况 | 显示 |

三条「不显示」各有理由：

- **空框不显示**：没有内容可清，多一个图标只会变成视觉噪音
- **禁用态不显示**：控件不可交互，按钮也不该可点
- **只读不显示**：清掉用户无法重新输入的内容是破坏性操作。为此另提供 `McaReadOnlyTextField`，只读字段按契约不带清空按钮，但保留与周围一致的排版和描边

### 行为

- 点击清空调用 `onValueChange("")`，**与键盘输入同一通道** —— 调用方的校验（如「temperature 必须是数字」）、脏标记、状态恢复都不会被绕过
- 无障碍名是 `McaActionLabels.CLEAR`（「清空输入」），并继承 `McaIconButton` 的触感反馈
- 参数名与 `OutlinedTextField` 一致，迁移就是改一个符号

## 4. 迁移结果

```
使用 McaTextField 的文件：35
迁移调用点：91
剩余原生 OutlinedTextField：2（均为契约内声明保留）
剩余原生 TextField：0
```

### 保留原生的 7 处（不是遗漏）

| 场景 | 原因 |
|---|---|
| `McaTextField.kt` | 封装自身的实现 |
| 负面提示词输入框 | 用 `TextFieldValue`，需要保留选区与输入法组合状态；`McaTextField` 只接收 `String` |
| Agent 首页输入区、问题卡片输入区 | 无边框自绘，样式由调用方完全定制 |
| 聊天输入框 | 承载附件芯片与富交互，不是普通表单字段 |
| 翻译草稿区、生图提示词区 | 无边框、带主题色强调的自绘输入区 |

判据：**如果替换后需要给共享组件加一堆只服务这一处的参数，那这一处就该继续用原生控件。**

## 5. 顺带修掉的既有缺陷

`core:designsystem` 的 `McaIconCraftContractTest` 里有一条测试抛 `StackOverflowError`。用 `git stash` 隔离验证过，**此缺陷在本次改动之前就存在**。

根因：它用一条整文件大正则扫描 2130 个 `src/main` 文件，三引号块分支叠加转义字符串分支，在 JVM 正则引擎上造成灾难性回溯。改为**线性词法扫描**（逐字符处理块注释、行注释、三引号、普通字符串），语义不变，现在 `core:designsystem` 全测试通过。

### 已知缺口

**清空按钮的实际手感没有做真机逐页面确认。** JVM 单测只能证明结构与契约（`McaTextFieldContractTest`），点击热区（40dp）与输入框内边距的配合、以及 91 处调用点在各自版面里的观感，需要在真机上逐页观察。
