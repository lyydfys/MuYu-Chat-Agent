# MCA v0.3.0

**从“聊天 + 模型管理 + 生图”升级为完整的本地 AI 工作区。**
本地 Agent、内嵌 DSH、Wan 2.2 视频、MediaTek / Anima NPU、Qwen-Image /
GenieX 路线、全新“关于”页，以及可审计的 release 构建链，全部进入同一个
`0.3.0`（versionCode 9）。

- 发布日期：2026-11-02
- 上一版本：`v0.2.4`（versionCode 8）
- 发布包：`MCA-v0.3.0-arm64-v8a.apk`
- 适用设备：Android `arm64-v8a`，minSdk 26
- 许可证：MIT（模型与第三方资产见文末）

---

## 1. 一句话看懂 0.3.0

0.2.4 是一个“可用的本地聊天 / 生图工具”；0.3.0 是一个“可扩展的本地 AI
工作区”：

- 能跑 Agent，不只是聊天；
- 能内嵌 DSH 工作区，不只是单页对话；
- 能生成视频，不只是图片；
- 能接 MediaTek NPU / Anima、Qwen-Image、GenieX、LiteRT 等多条加速路线；
- 有独立的“关于”页、GitHub 更新检查、Star 引导和赞助入口；
- Release 构建带 provenance、SBOM、16 KB page 审计和可复核签名。

## 3. 重点能力

### 3.1 本地 Agent：从“诊断页”到完整运行时

- 新增 `:core:agent-contract`、`:core:agent-runtime`、`:feature:agent-workspace`。
- 支持工具调用、MCP、记忆、审批门、工作流、会话轨迹和独立工作区。
- 模型生命周期、Provider、状态写入仍走现有单一所有权；没有第二套 Agent
  Owner、图片队列或状态 writer。
- 适用场景：本地模型上的多步任务、文件/设备工具、可审计的 Agent 执行。

### 3.2 内嵌 DSH：把 DeepSeek Harness 放进应用

- 新增 10 个 DSH 模块、`:api:dsh-gateway` 和 `:feature:dsh-workspace`。
- 覆盖 WebView/VScreen、浏览器、无障碍、Android actions、jobs、SAF、
  维护与中断恢复。
- 运行/回滚、强杀恢复等链路有设备证据；“双版本内容升级”仍未闭环，按开发
  预览能力使用，Provider 凭据和工作区配置由用户控制。

### 3.3 视频工作区：Wan 2.2 真正出片

- Wan 2.2 TI2V-5B 文/图生视频，外置 `stable-diffusion.cpp` 引擎。
- 支持模型资产下载与 SHA-256 校验、Turbo LoRA、VAE 分块、图编辑器和
  前台生成 worker。
- 480p 全 VAE 已在本机与设备侧出片；每步进度、取消、失败恢复有独立测试。
- 模型权重不入 APK，由用户在应用内下载；V1 的完整规格仍有未闭合项。

### 3.4 图像与加速器：多路线并存

- Qwen-Image 2.1、MNN-Diffusion、QNN/HTP、LiteRT Qualcomm、
  MediaTek NPUG/DLA、Anima CPU/NPU。
- Anima v4 固定/动态包：下载前许可确认、二选一、SHA-256 校验、断点续传；
  衍生包在 ModelScope 按 CircleStone 非商业许可发布。
- GenieX QNN、LiteRT/Qualcomm、MediaTek Neuron 等运行时按真实设备加载与
  smoke 结果决定可用性；设备型号只用于推荐和记录，不做下载/运行黑名单。

### 3.5 模型中心：更细的下载与许可控制

- 推荐过滤/排序、变体选择、固定/动态包、许可门、ModelScope/HF 镜像。
- 断点续传、大小/SHA-256 校验、失败保留与恢复。
- 模型推荐卡片与本地 bundle 关联，支持“已安装 / 重新校验 / 校验失败重试”。

### 3.6 全新“关于”页（本版新增）

在“设置 → 关于”中集中提供：

- 应用名称、版本、当前/最新版本状态；
- **检查更新**：直接读取 GitHub Releases，复用现有 `AppUpdateOwner`；
- **更新记录**：展示发布说明弹窗；
- 主作者、开源仓库、赞助支持、意见反馈四张卡；
- 可关闭的 **Star 引导**（“如果 MCA 帮到了你，请在 GitHub 点个 Star”）；
- 与参考稿一致的赞助弹窗：标题/副标题、去赞助、去点 Star、分享项目、
  意见反馈、自愿说明和关闭；“去赞助”打开本仓库的 `docs/DONATE.md`；
- **国内网络优化**：更新检查、Release 页面、赞助页和 Star 入口默认使用
  `gh-proxy.com` 加速链接；更新 API 失败时自动回退官方 `api.github.com`，
  APK 与校验文件下载同样优先走加速地址。个人主页与 Issues 页面不被该镜像
  代理，仍保留 GitHub 官方地址；
- **Star 教程**：三步引导弹窗（打开仓库 → 登录或注册 GitHub → 点击右上角
  Star），支持复制仓库链接，镜像不可用时给出原站备用地址；
- 支付宝 / 微信赞赏码：默认折叠，点“扫码赞助（国内可直连）”后离线显示，
  同一组图片也用于 GitHub `docs/DONATE.md`；
- 版本信息：当前版本、最新版本、上次检查、自动检查、开源许可。

关于页不新增第二套更新流程；版本、下载、校验、安装仍由现有更新 owner 负责。
Star 关闭状态和“跳过版本”只保存在本机 UI 偏好中，不进入模型/应用状态库。
GitHub 加速仅改写本仓库的受信任 URL；更新通道仍校验官方/镜像 endpoint 与
GitHub 资产域名，避免把任意地址伪装成更新源。

### 3.7 Local API、存储与 UI

- Local API 从 6 个源文件扩到 32 个，路由 golden 18 条，覆盖模型、聊天、
  图像、视频和 capability 发现；认证、隐私遮蔽与错误契约保持统一。
- Room 从 v21 升到 v35，新增 10 个 schema 快照；升级时自动迁移。
- 设计系统新增 McaButton / McaDialog / icons / motion 等共享组件；设置、
  模型中心、聊天、图片和视频页面完成一轮一致性与无障碍整理。

### 3.8 Release 工程与测试

- Wan 引擎以 **46.6 MB 压缩归档** 收入仓库，`unpackWanEngine` 在打包前
  校验归档和每个 `.so` 的 SHA-256 并解压；不需要 LFS，也不受 GitHub
  100 MB 单文件限制。
- Release 构建包含 source provenance、SBOM、16 KB page-size 审计、APK
  证书校验和 mapping/符号归档。
- CI 使用 JDK 21、submodule 递归、NDK/CMake、lint 和 QNN stub 路径；生产
  native 验收仍在受控环境执行。

## 4. 升级与兼容性

### 4.1 可以直接覆盖安装

- 包名：`com.muyuchat.mca`
- 签名证书：`2619ac4ce0ad8397b84c77df6ba165801fd4fab1460470f22f1eb7b3e4f9a9cf`
- versionCode：**8 → 9**
- versionName：**0.2.4 → 0.3.0**
- ABI：`arm64-v8a`

安装方式（二选一）：

1. 在文件管理器中直接打开 `MCA-v0.3.0-arm64-v8a.apk`，选择“更新/安装”；
2. 使用 adb：`adb install -r MCA-v0.3.0-arm64-v8a.apk`

**不需要卸载旧版本。** 覆盖安装会保留应用数据、模型、聊天记录、图片和设置。
本版已实测：

- 设备：`98a37aa7`（SM8750P）
- 从 `0.2.4-diag / vc8` 覆盖到 `0.3.0 / vc9`：`adb install -r` 返回 `Success`
- `firstInstallTime` 保持 `2026-10-03 02:25:09`，`dataDir` 不变
- 安装后证书仍为 `2619ac4c…`，与已发布的 v0.2.4 包一致
- 关于页及赞助二维码在真机可见、可交互

> 已发布的 GitHub `v0.2.4` 资产 SHA-256 为
> `0d5f566ac6109a4a42b47d256bde9afda1f662f4d633db20f9f15d1fb93bb065`，
> 证书同为 `2619ac4c…`，因此正式版用户可以直接升级。

### 4.2 数据迁移与备份

- Room 会从 v21 自动迁移到 v35；迁移包含 Agent 与图片/聊天/文件相关表。
- 首次启动新版本时，建议保留足够磁盘空间并完成一次备份（设置 → 数据管理 /
  备份与同步），再执行大规模模型或视频任务。
- 更新不会删除 `data/`、本地模型、聊天、图片、文件库或设置。
- 若从极旧的调试包（非同一签名）升级，Android 会拒绝覆盖；请先导出数据，
  再按调试包说明处理。正式发布包之间使用同一签名，可直接覆盖。

### 4.3 关于页的更新检查

首次进入“设置 → 关于”会自动检查一次 GitHub Releases；也可以手动点击
“检查更新”。发现新版本时提供发布说明、立即更新、跳过此版本和打开 GitHub
Release；当前版本领先于最新发布时显示“已是最新稳定版”。

更新检查默认请求 `gh-proxy.com` 加速的 GitHub Releases API；若镜像超时、
返回非 2xx 或响应无法解析，会自动回退到官方 `api.github.com`。APK 与
`.sha256` 校验文件也优先使用加速地址，并在每一步校验 GitHub HTTPS 域名、
文件名、大小和 SHA-256；镜像不可用时整个更新流程仍可走官方通道。

## 6. 已知边界

- JVM 门禁和 release 构建不等于全部真机验收。以下事项仍可能为
  `NOT_RUN` 或 `BLOCKED`：
  - Agent 工具链在低吞吐模型上的长任务表现；
  - DSH 双版本内容升级与部分 Provider/网络场景；
  - Wan V1 全部产品规格（480p 全 VAE、LoRA、取消/恢复已分别验证）；
  - Anima step 6、部分 MediaTek/QNN 设备的真实 native load/graph smoke。
- QNN、MediaTek、Anima 和实验图像包由首次真实加载/执行决定兼容性；设备
  型号只用于推荐，不构成下载或运行白名单。
- 视频模型权重、Anima 衍生物和云端凭据均不随 APK 分发；使用前请阅读各自
  许可、服务条款和隐私说明。
- 关于页的“最新版本”来自 GitHub Releases 的最后一个正式稳定版；发布新
  Release 后刷新“检查更新”即可看到。
