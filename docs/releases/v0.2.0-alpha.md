# MCA v0.2.0-alpha

Smart web search, role-card assistants, and local API compatibility hardening.

## Highlights

- Added smart web search with manual, smart-auto, and always-on trigger modes.
- Added direct public URL reading, source cards, retrieval trace cards, citation
  audit, source quality scoring, and local search diagnostics.
- Added provider configuration for SearxNG, Brave Search, Tavily Search, Jina
  Search, and custom JSON search gateways.
- Added URL-template support for custom JSON gateways, including
  `/search?q={query}&limit={max_results}` and common `q/query/max_results`
  parameter fallbacks.
- Expanded custom JSON parsing for common search gateway fields, including
  nested `source.url/title`, `summary`, `excerpt`, `pageContent`, and common
  URL/title aliases.
- Added network preflight, current-form testing, closed-loop self-test, public
  protocol self-check, backup providers, and troubleshooting advice.
- Added local assistants with role-card import/export, default model preference,
  generation parameters, and per-assistant web-search capability.
- Added import compatibility for common nested character-card `data` fields by
  converting description, personality, scenario, first message, and examples
  into an MCA system prompt.
- Hardened the local OpenAI-compatible API so third-party clients keep their
  own system prompt and inline image data URLs when forwarding multimodal chat.
- Extended chat persistence for assistant IDs, image attachments, source
  references, and web-search traces.

## Known Limits

- Web keyword search requires a user-provided provider key or trusted/self-hosted
  search endpoint; the public JSON self-check source is only a protocol test.
- Public SearxNG instances can rate-limit, block JSON, or change behavior.
- Web search does not let the model browse freely; MCA fetches and injects
  source summaries into the current turn only.
- Local image generation remains experimental and still requires complete model
  bundles with diffusion model, VAE/AE, and text encoder/LLM components.
- Local vision requires a compatible multimodal GGUF model and matching
  projector file; text-only GGUF models cannot identify images.
