# MCA v0.3.5

**聊天体验修复 + 酒馆预设兼容 + DSH 对标补全。**

- 发布日期：2026-11-04
- 上一版本：`v0.3.4`（versionCode 13）
- 本版本：`0.3.5`（versionCode 14）
- 适用设备：Android `arm64-v8a`，minSdk 26
- 许可证：**Apache-2.0**

## 1. 聊天页

- **编辑并重发**：长按自己发过的消息 → 编辑 → 保存后该条之后的内容回退，并按编辑后的文本重新生成。正在生成时不可编辑；持久化失败会明确提示，不会留下半截会话。
- **引用回复（QQ 式）**：长按任意消息 → 引用回复。输入框上方出现引用条（谁说的 + 前 60 字，可取消），引用作为结构化字段进入上下文并计入 token 预算，**只在这一轮有效**。
- **消息操作去重**：删掉了与「删除本轮」重复的入口，只保留语义更强的那一个。
- **「我说的话它总是漏」**：上下文准入改为**用户消息优先**——预算不够时先丢更早的助手长回复，而不是丢你的提问。
- **纯文本消息不再报「图片读取失败」**：历史消息里指向已删除图片的悬空引用会被剔除；气泡只显示浅色「图片已丢失」；只有你本轮自己选的图不可读才会报错，且不再泄露内部路径。

## 2. 世界书 / 上下文来源

- **批量导入**：多选后一次拉取、逐条导入并汇总（成功 N / 跳过重复 N / 失败 N），不再「一直跳、只留最后一个」。
- **重复检测**：按条目内容指纹判重（含关键词与开关，排除 id/书名/scope/时间），同内容换文件名、换作用域都能识别；重复的跳过不写库。同一批导入两次，第二次全部跳过。
- **来源面板显示书名**：标题改为书名/库名，UUID 只作为 `#c34f01` 这样的短面包屑；书被删后显示「原名（已不在当前资料库）」；知识库同理。

## 3. 酒馆（SillyTavern）预设

之前「在酒馆能用、在这全不能用」是三个原因叠加：解析器遇到越界值/`null` 直接抛异常导致整份失败；漏读 `openai_max_tokens`；提示词/行为字段被全部丢弃。

- 现在能识别并导入酒馆 chat-completion 预设：`temperature`、`top_p`、`top_k`、`min_p`、`repetition_penalty`、`presence_penalty`、`frequency_penalty`、`seed`、`stop`（含嵌套数组）、`openai_max_tokens`。
- 越界**钳制并逐项记账**，不再整份失败；不支持/忽略的键会在导入摘要里列出。
- **输出预算按模型区分**：导入保留作者声明的值（6 万 / 3 万 / 4.7 万原样保存），绑定**本地模型**时收敛到 8192（手机上下文装不下），绑定**云端模型**时保留声明值。
- **提示词包随预设保存**：`prompts` + `prompt_order` 按顺序展平（跳过 disabled 与 marker），存在预设 JSON 的 `prompt_appendix`，导入摘要显示字数。上限 32k 字。
- **仍不生效**：酒馆宏（`{{getvar}}`）、`regex_scripts` 输出改写、`<StatusBlock/>` 之类 HTML+JS 小剧场、`SPreset/entryStates` 扩展——需要一条完整的提示词流水线，属后续切片。

## 4. 生图

- **成功后清空输入框**，失败/取消保留；只清「仍是本次提交」的那条（期间你改过就保留）。
- **失败不再需要新开聊天**：提交前体检（存在/可读/大小/文件头/尺寸）、准入再体检、重试前复原快照再体检；失败/取消的 job 会清空图片引用，迟到回调不能复活。
- **预览可缩放**：双指 1–6x、双击 2.5x/还原、拖动夹紧、单击关闭；仍是采样解码，不整图进内存。

## 5. DSH 对标补全

- **命令审批**：危险命令不再只有静态拒绝——会在悬浮球上弹审批卡（脱敏命令名 + 30 秒倒计时），「允许一次」才执行，拒绝/超时/无窗口一律拒绝；开关关闭时退回「直接拒绝」而不是放行。
- **画中画**：整页 DSH 缩成系统小窗，不需要悬浮窗权限；控制台新增入口。
- **免 root 容器（部分）**：容器契约、检测、proot 参数翻译与控制台只读区块已完成；**本版不内置 proot 二进制与 rootfs**（二进制与许可证决策），缺失时如实显示 `MISSING_PROOT` / `MISSING_ROOTFS`。
- **ADB 配对（未接线）**：完成了 P-256 与 RFC 9382 SPAKE2 及配对状态机（RFC 官方向量全过），但核对 AOSP 后发现真实 adb 用的是「证书 TLS + ExportKeyingMaterial + Curve25519 SPAKE2 + AES-GCM」，与早期假设不同，因此**不接线**；`docs/architecture/DSH_ADB_PAIRING.md` 记录事实与三条路线。

## 6. 设置与可靠性

- **备份导出**：新增备份包格式（版本/时间/应用版本/六张表白名单行数/非敏感设置）与校验器；凭据与聊天正文不入包；设置页新增「备份与恢复」卡。**恢复入口当前只做校验，不会覆盖现有数据**。
- **局域网 API 限速**：同一地址 60 秒内 5 次鉴权失败 → 冷却 30 秒并回 `429` + `Retry-After`；成功即清零。
- **启动卡死修复**：外显端口改到 IO 线程绑定（此前在主线程读偏好并查询悬浮窗授权，会导致卡在「上次启动未完成」）。
