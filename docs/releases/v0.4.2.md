# MCA v0.4.2 — 修复富文本渲染导致的会话闪退

## 1. 一句话

修复一个**打开会话就闪退**的崩溃：消息里出现无值属性的富文本标签（如 `<details open>`、`<div data-x>`）时，解析器读取了不存在的正则捕获组，抛 `IndexOutOfBoundsException: No group 6`。

## 2. 崩溃现场

```
FATAL EXCEPTION: main
Process: com.muyuchat.mca
java.lang.IndexOutOfBoundsException: No group 6
	at java.util.regex.Matcher.group(Matcher.java:589)
	at ...RichBlockSanitizer.safeAttributes(...)
```

用户感知：某个会话**一进去就闪退**，反复重开同样崩。

## 3. 根因

`feature/chat/src/main/java/com/muyuchat/feature/chat/RichBlockSanitizer.kt`

```kotlin
// L590：这个正则只有 5 个捕获组
val ATTRIBUTE = Regex(
    "([A-Za-z_:][-A-Za-z0-9_:.]*)(\\s*=\\s*(?:\"([^\"]*)\"|'([^']*)'|([^\\s\"'>]+)))?"
)
//  ↑组1 属性名      ↑组2 整体值   ↑组3 双引号 ↑组4 单引号 ↑组5 无引号

// L372-375：取值兜底链却读到了第 6 组
val value = match.groupValues[3]
    .ifBlank { match.groupValues[4] }
    .ifBlank { match.groupValues[5] }
    .ifBlank { match.groupValues[6] }   // ← 越界
```

`groupValues` 长度 = 捕获组数 + 1 = 6，合法下标 `0..5`，`[6]` 必然抛异常。

**触发条件**：标签属性带**没有值**的形态（`<details open>`、`<div data-x>`）时，前三种带引号形式都匹配不到，才会走到 `[6]`。带引号属性（`title="x"`）不会触发，所以不是每条消息都崩。

## 4. 影响版本

**不是 0.4.1 独有**。引入缺陷的提交是 `007c9c56`（2026-11-05，「`<StatusBlock>`/`<details>` 小剧场结构化显示」），包含该提交的 tag：

```
v0.3.7  v0.3.8  v0.4.0  v0.4.1
```

即 **0.3.7 起的所有版本都会崩**。0.4.1 只是因为是最新发布版而被撞见。

## 5. 修复

```kotlin
    .ifBlank { "" }   // 没有第 6 组，直接返回空字符串
```

## 6. 验证

**回归测试**（新增 `valueless attributes do not crash the sanitizer`）覆盖 `<details open>` 与 `<div data-x>` 两种无值属性：

| 步骤 | 结果 |
|---|---|
| 临时还原缺陷（`[6]`） | 该测试 **FAILED**（23 tests / 1 failed） |
| 恢复修复 | **23 tests 全过** |

反向验证证明这个测试确实能抓住该缺陷，不是形式化断言。

**全仓排查**：扫描 `groupValues[N]` / `.group(N)` 共 23 处引用，逐处核对所属正则的组数——只有这一处越界，其余均在范围内。

## 7. 升级建议

- 凡在 0.3.7 ~ 0.4.1 之间被"某会话打不开"困扰的用户，升级即可恢复
- 数据无需迁移：崩溃发生在渲染期，未写入任何损坏状态
