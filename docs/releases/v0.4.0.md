## 1. DSH 网页双内核（GeckoView）

控制台新增「DSH 网页内核」，可在**系统 WebView**（默认）与 **GeckoView** 之间切换，切换持久化。

- 依赖钉在 `org.mozilla.geckoview:geckoview-arm64-v8a:153.0.20260810162159`。**不是最新版**：
  155/157/159 的 `aar-metadata` 要求 compileSdk 37，本项目是 36；实测 153 及更早声明
  `minCompileSdk=1`。升级 GeckoView 必须先升 compileSdk，两者不能分开动。
- 两个内核加载**同一个已签名 URL**，鉴权、token 规则、导航围栏完全共用；切换只换渲染引擎。
  GeckoView 有独立 Cookie 罐，切换后需重新登录 DSH 一次。
- 回落策略是纯函数（`DshWebKernelPolicy`）：非 arm64、或构建没打构件时，控制台显示原因并
  继续用系统 WebView，不会空白、不会崩。默认内核是系统 WebView。
- GeckoView 路径**不做** WebView 专属能力：JS 对话框、文件选择器、平台下载监听、账号回复
  DOM 探针、弹窗预开。外链仍走系统浏览器。这也是默认仍旧用 WebView 的原因。
- 成本：AAR 91.5 MB（`libxul.so` 解压后 147 MB），安装后占用明显增加。

## 2. 免 root 容器：六步安装流水线，真机 Ubuntu 24.04.5 可运行

- `scripts/dsh/stage-container.ps1` 拉取 proot 5.1.107.102 + libtalloc 2.5.0 +
  libandroid-shmem 0.7（termux-main aarch64）与官方 `ubuntu-base-24.04.5-arm64`，逐个校验
  SHA-256；**二进制与镜像不进 Git**，APK 实测增量约 29 MB（不是此前估计的 200 MB）。
- `DshContainerInstaller` 六步：校验资产 → 准备目录 → 解包 rootfs → 校验结构 → 原子提交
  （保留 `rootfs.previous`）→ 自检探针；幂等复用、失败点名步骤；解包拒绝绝对路径 / `..` /
  经符号链接越界。
- **真机结论：容器能跑**。早先“被 W^X 挡住”是误诊 —— proot 不 exec guest 程序，它 exec 自己的
  **loader** 去 mmap guest ELF；`PROOT_LOADER` 未设置时 loader 被写到临时目录，那一次 exec 被
  SELinux 拒绝，错误却报成了 guest 路径。把 proot 包里的 `libexec/proot/loader` 作为
  `libproot_loader.so` 打进 jniLibs 后整条链打通，targetSdk 无需改动。
  真机（`98a37aa7`）：`PRETTY_NAME="Ubuntu 24.04.5 LTS"`、`aarch64`、`/usr/bin` 下 292 个程序可执行。
  详见 `docs/architecture/DSH_CONTAINER.md` §2.1。

## 3. 修掉一个让测试"假绿"的真 bug

`DshAdbPairingConsoleTest` 里有两处游离的单引号，导致 `:feature:dsh-workspace` 的单测源码
**根本编译不过**——上一批声称的「7178 测试全过」并没有真正运行这个模块。修好语法后暴露的
11 个失败已逐个处理：

- `package.json` 解析器无法识别嵌套对象的 `key: value`（`devDependencies` / `scripts` /
  对象版本），整份文档被判为不可读；`dependencies` 内层循环不消费右花括号，导致「JSON 之后
  存在多余内容」。改为递归 `skipObject`/`skipArray` 并补齐右花括号、`{}` 空对象、尾随逗号规则。
- `node_modules` 列表排序：作用域包优先、点目录次之（原来按裸名排序把 `.bin` 排到 `@scope/name` 前）。
- 两处过期断言按新契约重写（不是删除）：ADB 端口用 `UNVERIFIED` 显式走「未验证假设」分支；
  设备拒绝路径改为断言具体原因码且**不得**回落到假设文案。

## 3.1 应急恢复（⑧ 收尾）

控制台新增「应急恢复」区块：按运行时报告的失败码给出**有序、最小破坏**的修复计划
（移动家目录 → 重装内置负载 → 退回自带负载 → 仅导出诊断），会动用户数据时二次确认。

- 决策层 `DshEmergencyRecovery`（9 个测试）与执行器 `DshEmergencyRecoveryRunner`（7 个测试）是纯逻辑
- app 侧 `DshEmergencyRecoveryAdapter` 提供四个真实效果：停机并确认 `STOPPED`、家目录**改名不删除**、
  重装内置负载并检查 `READY`、退回自带负载
- 契约要求"需确认的计划"必须带 `confirmed=true` 才执行

**脚本更新与验签口径**：本项目没有独立的脚本签名体系。完整性来自 **SHA-256 清单**
（`archiveSha256` + `criticalFiles` 逐文件哈希），清单随**已签名的 APK** 分发 ——
安全等级等价于 APK 签名。引入 Ed25519 独立验签属于新增信任链（发布侧私钥 + 内置公钥），
不在本版范围。

## 3.2 迭代效率

- `-PmcaIteration=true`：跳过 R8 / 资源压缩 / native 符号 / lintVital，但保留 release 签名，
  产物可直接 `install -r` 覆盖 → 打包 40 分钟降到 3~8 分钟
- `am broadcast -a com.muyuchat.mca.RUN_CONTAINER_INSTALL`：一条命令跑完六步安装并打时间轴，
  正式包内恒关闭（`BuildConfig.MCA_ITERATION == false`）
