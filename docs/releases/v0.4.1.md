# MCA v0.4.1 — DSH 内核升级到官方 0.2.2-rc.1

## 1. 一句话

内置的 DeepSeek Harness 内核从参考包的 `0.2.1-rc.2`（bundle 形态）升级为**官方 `0.2.2-rc.1`**（329 个独立包），并完整保留原先 4 个 Android 专有工具包 —— **能力零丢失，包体只增 20 MB**。

## 2. 为什么升

官方 `0.2.2-rc.1`（2026-11-04）第一条变更就是移动端：

> 完善手机和平板适配，优化软键盘交互、导航与窄屏布局，保持菜单和操作入口可用。

同版本还带来：消息在宿主确认接收后才清空草稿（发送期间输入框只读、失败保留草稿）、
输入框统计可展开查看完整值、工作步骤收起后保留助手文字、侧栏触摸与键盘操作改善、
图片上传进输入框即开始、搜索优先长摘要等。

## 3. 能力核对（"不丢失能力"的证据）

| 能力 | 状态 | 证据 |
|---|---|---|
| 内核启动 | ✅ | 真机六阶段：`NODE_PROCESS_ALIVE → PORT_LISTENING → HTTP_AUTHENTICATED → PLUGINS_LOADED → READY → FIRST_FRAME_RENDERED` |
| Android 系统工具 | ✅ 2 个 | `android_usage`, `android_overlay` |
| Shizuku 工具 | ✅ 4 个 | `shizuku_status`, `android_notify`, `android_setting_app`, `android_clipboard` |
| 无障碍工具 | ✅ 12 个 | `android_a11y_status`, `android_screen`, `android_tap`, `android_type`, `android_back`, `android_home`, `android_scroll`, `android_swipe`, `android_hold`, `android_touch`, `android_gesture`, `android_touch_status` |
| 虚拟屏工具 | ⚠️ 条件注册 | 6 个，仅当 `ROOT_AVAILABLE=1` 或 `SHIZUKU_AVAILABLE=1`；无特权时按设计不注册并打警告 |
| 双内核 Web UI | ✅ | GeckoView / 系统 WebView 切换与回落不变 |
| 终端、Agent、插件管理 | ✅ | 未改动，沿用 |

工具注册可用 `scripts/dsh/probe-android-tools.mjs` 在任何机器上复现。

## 4. 为 Android 做的两处适配（官方包不为 Android 设计）

**① `node-addon-require-builtin` 无 Android 产物**

官方通过平台可选依赖加载 Node-API addon，`optionalDependencies` 只列了 darwin/linux/win32。
`dsh-app-boot` 在 host preparation 阶段无条件调用，缺少时直接致命：

```
Cannot find module '.../napi-v9-android-arm64/require_builtin.node'
dsh: FAILED NODE_START_FAILED (code 1)
```

修法 `scripts/dsh/patch-payload-android.mjs`：原生绑定优先，缺失时回退到 `libdshnode.so`
的 `--expose-internals` 路径（同一批内部模块可直接 `require`）。补丁幂等、带形状校验，
内核再升级时形状不符会直接失败而不是静默产出坏包。

**② 载荷裁剪误删代码目录**

第一版裁剪把所有名为 `doc/docs` 的目录当文档删除，结果删掉了 `yaml/dist/doc/`（真代码），
内核崩在 `MODULE_NOT_FOUND`。修法 `scripts/dsh/prune-payload.mjs`：只删 `*.map`、`*.d.ts`、
`*.md`（保留 `LICENSE*`）以及**包根**下的 `test/tests/__tests__/examples`，
深层 `doc/`、`lib/test/` 一律保留。

## 6. 打包可复现步骤

```powershell
# 1) 取官方闭包（本机 Node >= 24.9）
npm install '@deepseek-ai/dsh@0.2.2-rc.1' --omit=dev --ignore-scripts --os=android --cpu=arm64
# 2) 安全裁剪
node scripts/dsh/prune-payload.mjs <node_modules>
# 3) 放入 4 个 Android 工具包（已 vendor 到 third_party/dsh/android-tools）
# 4) Android 适配补丁
node scripts/dsh/patch-payload-android.mjs <payload>/dshroot/lib/node_modules
# 5) 打包（恒 '/' 分隔符、确定性排序）
python scripts/dsh/pack-payload.py <payload-dir> <out.zip>
# 6) 重算清单
python scripts/dsh/regenerate-payload-manifest.py <zip> <payload-dir>
```

## 7. 验收判据（本次采用）

以前把旧进程的日志当成"新载荷可用"是错的。现在必须三条同时满足：

1. `force-stop` 后冷启
2. 日志出现 `payload … installed archive=<新哈希>`，且哈希与 `MANIFEST.json` 一致
3. 六个 stage 全部出现，最后一条是 `FIRST_FRAME_RENDERED`

本次双机（平板 `98a37aa7`、手机 `f9d98aa3`）均满足。

## 8. 已知限制

- 虚拟屏需要 root 或 Shizuku；`/data/local/tmp/vscreen_shizuku.jar` 不在载荷内（参考仓库已不可用），
  因此该能力的**执行**会如实报不可用，**注册**不受影响。
- 官方 0.2.2 有两处插件接口破坏性变更（`tools.resolve/executable`、`tools.mode`/`DSH_TOOLS_MODE`）。
  我们这 4 个工具包只用 `ctx.tools.register(defineTool(...))`，不受影响；但第三方插件升级时需注意。
- 语言/文案新版本增加了日语、西班牙语、法语、德语、俄语、巴西葡萄牙语，MCA 目前仍以中英为主。
