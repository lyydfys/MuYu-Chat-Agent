# MCA v0.3.2

**修复版本 + 功能版本：修复云端模型发送闪退与多处同类崩溃，世界书与预设支持批量导入，并带来可管理的酒馆生成预设库、云端生图模型列表、设置页仪表盘与分片并行更新下载。**

- 发布日期：2026-11-03
- 上一版本：`v0.3.1`（versionCode 10）
- 本版本：`0.3.2`（versionCode 11）
- 适用设备：Android `arm64-v8a`，minSdk 26
- 许可证：**Apache-2.0**（`0.3.0` 及更早版本仍为 MIT）

## 0. 本次闪退修复

### 0.1 云端模型一点发送就闪退

发送链路取活动会话用的是 `chatSessions.first { ... }` 加 `requireNotNull(snapshot)`。当活动
会话 id 指向一个已不在列表里的会话（存储读取失败、旧快照恢复出的已删除会话、并发重置）时，
这两行在生成的协程里抛出 `NoSuchElementException` / `IllegalArgumentException`，异常逃逸成
未捕获异常，进程被系统直接杀掉。

本版：

- 两处改为可失败查找，失败时走既有收敛路径（状态栏提示 + 终止本轮），不再抛异常；
- 两个提交协程（多附件预检与常规路径）补上 `catch`，提交前任何异常都变成可见状态行。
  此前它们只有 `finally`，上下文组装、准入或会话持久化抛错都会直接崩进程；
- 上下文摘要阶段的 `checkNotNull(cloudConfig)` 改为显式取消，模型在压缩途中被删除不再 NPE。

### 0.2 同批排查的易闪退点

- 助手列表为空时读取选中助手（`assistants.first()`）；
- 删除最后一个助手（`remaining.first()`）；
- 失败回滚时恢复会话（`durableSessions.first { }`）；
- 回放投影的空块列表（`blockBranches.first()`）；
- Markdown 渲染的 `!!` 与空 token 索引；
- 生图提交的空结果集（`generatedImages.first()`）。

## 0.3 批量导入

- **世界书**：选择器改为多选，一次可选多个导出文件；逐文件导入，单个失败不影响其余，
  状态栏报告「已导入 N 本，M 本失败」；
- **生成预设**：预设页「导入预设」改为多选，一次选择只做一次存储读改写；
- 预设删除与绑定保存移到 IO 线程（此前在点击回调里同步磁盘写入）。

## 1. 生成预设管理

酒馆（SillyTavern）文本生成预设从"一次性导入"变成可管理的资产：

- 应用菜单新增「预设管理」入口，进入独立全屏页面；模型管理页新增「预设」分节，
  两个入口读取同一批记录；
- 支持导入、重命名、绑定本地/云端对话模型、删除；
- 预设只保存采样与输出参数（温度、top_p、top_k、输出长度、惩罚项、停止词等）；
  提示词、模板和宏仍由角色卡导入；
- 绑定保存后把预设的语义字段写进对应模型的生成参数档案，**模型档案仍是运行时权威**，
  角色卡覆盖依旧优先于预设；
- 记录写在独立命名空间 `mca_generation_presets_v1`，带 schema 版本字段，逐条容错解析，
  不猜测旧格式，也不改写任何既有配置文件；
- 删除预设不会回退已应用到模型的参数，弹窗与状态栏都已写明。

## 2. 云端生图引擎可拉取模型列表

此前只有云端**聊天**引擎能在编辑器里「获取模型列表」，**生图**引擎必须手敲模型名。

- 图像引擎编辑器新增「获取图像模型列表」按钮，结果进入同一个可点选的模型选择弹窗；
- 图像表单使用独立的 `imageApiFormat`，因此不复用聊天传输层：DashScope 原生根地址
  （`https://dashscope.aliyuncs.com`）的模型列表在 OpenAI 兼容前缀
  `/compatible-mode/v1/models` 下，直接请求原生根会 404，本版自动补正；
- 兼容 `data[].id`、`models[]` 和纯字符串等常见返回结构，去重并限制条数；
- 只读操作：拉取不影响表单状态栏，失败信息显示在按钮下方。

## 3. 设置页改为分区仪表盘

- 六个分区（运行、日志与诊断、隐私与数据、联网检索、实验功能、关于）从一条横向
  标签条改为**仪表盘卡片网格 + 全屏详情页**，每个分区卡片显示当前状态徽标；
- 详情页支持下拉手势与系统返回键回到仪表盘，分页状态在切换中保持；
- 冻结的标签、入口顺序与文案保持不变；新增的分区摘要为仪表盘所需；
- 隐私清理控件改为跟随清理 owner 的单飞槽位：当其他清理占用槽位时，清理按钮与
  前缀缓存开关一律禁用而不是静默丢弃点击；已武装的二次确认会被撤销，
  避免等待结束后一次点击直接清库；
- 关闭持久化前缀缓存被单飞槽位挡住时，状态栏给出明确提示，不再出现"开关点了没反应"。

## 4. 应用更新下载加速

- 495 MB 的更新包在单连接代理下只有几十到几百 KB/s。本版加入 8 路 HTTP Range
  并行下载：分片级断点续传、`Content-Range` 校验、合并后原子移动、取消不被吞掉；
- `≥32 MB` 的资产先尝试并行，失败按 URL 逐个回退到原有单流下载；
- 通过受信任的资产 API 302 解析出 `release-assets.githubusercontent.com` CDN 直链，
  只接受白名单跳转；国内资产镜像切换到 `ghproxy.net`（`gh-proxy.com` 仍可用于 API）；
- 关于页显示下载进度条、实时速度与预计剩余时间。

## 7. 已知边界

- **闪退修复未经真机复现验证**：原始崩溃未拿到 logcat，结论来自对发送链路的静态定位与
  同类抛出点排查；如仍复现，需要用户提供 `adb logcat` 崩溃栈。
- 预设页与设置仪表盘尚未在真机上做视觉基线与大字体、深浅色验收；
- 预设与绑定仍是 `load → 改内存 → save` 序列，并发导入理论上可丢记录（已改为单次
  批量写入，降低窗口）；
- 批量导入的多选行为未在真机文件选择器上验证，OEM 契约可能存在差异；
- 生图模型列表复用各家 OpenAI 兼容的 `/models`；不自建该端点的服务商会返回 404，
  此时仍需手填模型名；
- 并行下载依赖服务端支持 Range；不支持时自动回退单流；
- 本地模型、图片、视频后端未在本次重新跑真实推理，相关结论沿用 `0.3.1`。
