# MCA v0.3.9

**内置 proot + Ubuntu 24.04 根文件系统：六步安装流水线，容器在应用自己的 uid 上跑起来**

- 发布日期：2026-11-05
- 上一版本：`v0.3.8`（versionCode 17）
- 本版本：`0.3.9`（versionCode 18）
- 适用设备：Android `arm64-v8a`，minSdk 26
- 许可证：**Apache-2.0**（随包的 proot 为 GPL-2.0-or-later，见下）

---

## 1. 不再要求"用户自备 proot 和 rootfs"

1.0 的容器文档把 proot 与 rootfs 留在"用户自备"，因为随包分发第三方二进制属于**资产与许可证
决策**。该决策已完成：

| 资产 | 来源 | 版本 | 许可证 |
| --- | --- | --- | --- |
| `proot` | `packages.termux.dev` termux-main/aarch64 | 5.1.107.102 | GPL-2.0-or-later |
| `libtalloc.so` / `libandroid-shmem.so` | 同上（proot 的运行时依赖） | 2.5.0 / 0.7 | LGPL-3.0-or-later / Apache-2.0 |
| Ubuntu base rootfs | `cdimage.ubuntu.com` ubuntu-base 24.04.5 LTS (noble) arm64 | 24.04.5 | Ubuntu 基础镜像；组件许可证在镜像内 `/usr/share/doc` |

- **不进 Git**：`.gitignore` 排除 `core/dsh-runtime/src/main/jniLibs/` 与
  `app/src/main/assets/offline/`。构建前跑一次 `scripts/dsh/stage-container.ps1`，
  脚本内置每个 URL 的 SHA-256，哈希不符即硬失败。
- **APK 增量约 30 MB**（rootfs 归档 29,936,675 字节 + 三个二进制约 308 KB），
  解包后占用应用私有目录约 80 MB。此前文档估算的"~200 MB"没有实测依据，实际小得多。
- **GPL-2.0 义务**：proot 以独立可执行文件随包分发；发布记录带 `container-manifest.json`
  里的 `sourceUrl`，用于提供对应源码。MCA 不对 proot 主张著作权。

## 2. 打包形态受 SELinux 约束

targetSdk 36 下应用**不能**执行应用可写目录里的 ELF（`app_data_file` 的 `exec_no_trans` 被拒），
所以 proot 只能放在 APK 的 `nativeLibraryDir`：

- proot 以 `libproot.so` 随包，由 PackageManager 解包到可执行目录；
- 两个依赖用**原始 SONAME**随包（`libtalloc.so` / `libandroid-shmem.so`），动态加载器按名即可找到；
- 三者在 `packaging.jniLibs.keepDebugSymbols` 里**无条件**保留——对可执行文件 strip 没有意义，
  且可能破坏入口；
- rootfs 是**数据**：解包到 `files/dsh/container/rootfs`，由 proot 以 `-r` 读取。

## 3. 六步安装流水线

控制台「免 root 容器（proot）」区块里点「安装内置 Ubuntu」：

| # | 步骤 | 失败意味着 |
| --- | --- | --- |
| 1 | 校验离线资产（schema + 流式 SHA-256 + nativeLibraryDir 里的 proot） | 这次构建没打资产，或资产被换过；**不解包任何东西** |
| 2 | 准备安装目录（清理上次崩溃留下的 `.staging`） | 存储不可写 |
| 3 | 解包 rootfs（带真实字节进度） | 归档损坏 / 格式不受支持 / 含越界条目 |
| 4 | 校验 rootfs 结构（`bin/sh` 必须存在） | 归档不是完整 rootfs |
| 5 | 原子提交（旧树 → `rootfs.previous`，写 `.install-state.json`） | 重命名失败 |
| 6 | 自检探针（唯一允许的 argv，要求退出码 0 且输出 `ok`） | proot 起不来（SELinux/缺库/rootfs 不完整） |

- **幂等**：同一归档且 `bin/sh` 存在时复用，只跑第 6 步。
- **可回滚**：旧 rootfs 保留为 `rootfs.previous`，新树起不来时旧树还在。
- **解包安全**：绝对路径、`..` 段、经符号链接父目录越界的条目一律拒绝；条目数与解压总量有上限。

## 4. 顺带修掉的一个真问题

`DshAdbPairingConsoleTest` 里有两处游离的单引号（`'`），导致 `:feature:dsh-workspace` 的
单元测试源码**根本编译不过**——也就是说上一批（`339bbac9`，ADB 配对/备份/传感器）声称的
"7178 测试全过"并没有真正运行这个模块的测试。语法已修复；由此暴露出的 **11 个既有失败**
（`DshPluginCatalogTest` 9 个 + `DshAdbPairingPortTest`/`DshAdbPairingConsoleTest` 各 1 个）
与本版改动无关，是上一批的遗留，需要单独一轮处理。

## 升级说明

- 覆盖安装即可，本地模型、聊天记录、预设与设置均保留。
- 容器资产是**新增**内容，首次使用需在控制台点一次「安装内置 Ubuntu」（解包约 80 MB）。
- 不跑 `stage-container.ps1` 也能构建：APK 变小，容器区块显示"缺少 proot"，安装按钮如实报缺资产——
  构建永远不会因为缺二进制资产而失败。
